# Flip Four — 列を反転できるガラスの四目並べ（スマホ用ブラウザゲーム）

受け取った要項。実装で変えた設計値と確かめた事実は `docs/design.md` に書く。

## 1. 目的
1台のスマホを2人で交代に触って遊ぶ四目並べ。起動すると、ゆっくり動くグラデーションの背景の前に、透明なガラスの盤（7列×6段）が少しだけ奥行きを見せて立っている。手番の人は、列をタップしてガラス玉を落とすか、その代わりに1列の上下を反転する。落とした玉は筒の中を落ちて底で2〜3回跳ね、「コツッ」と澄んだ音が鳴る。反転すると筒が手前に180°回り、中の玉は反対側の端から物理演算でまとめて落ち直す。例えば上から赤・青と並んでいた列は、上から青・赤になる。縦・横・斜めのどれかに4つ揃うと、揃った玉が光り、勝った側の色のグラデーションが画面に広がる。

## 2. 譲れないこと
- ガラス玉が本物のガラスに見えること。依頼の「フォトリアル」「リキッドグラス」の中心になるため
- 落下と反転の動きが物理演算で、音が小気味いいこと。手触りがこのゲームの価値だから
- 盤面のルール上の状態は純粋なロジックが決め、物理は見せ方だけにすること。物理の揺れで勝敗がずれないようにするため
- 縦向きのスマホで60fpsを保つこと。2人が同じ画面を交代に触るので、もたつくと遊びにならないため

## 3. 範囲とやらないこと
- 作る: 2人対戦（同じ端末）、落とす操作と反転する操作、勝ち・引き分けの判定と演出、もう一度遊ぶ、音のオン/オフ、手番の表示
- やらない: CPU対戦、オンライン対戦、カメラを回すこと、アカウント、スコアの保存、BGM、横向きの最適化、設定画面

## 4. 技術の構成と版
- TypeScript + Vite（静的ファイルとして配信）
- three.js（WebGLRenderer。WebGPURenderer は使わない）
- @dimforge/rapier2d-compat（WASM を同梱した版。物理は盤の面上の2D）
- 効果音は Web Audio API で合成する（音声ファイルと howler.js は使わない）
- テストは Vitest
- 画面の文言とコードのコメントは日本語

## 5. 手法メモ

### 芯1: GlassMarble（ガラス玉の見た目）
- 手法: screen-space refraction（画面空間の擬似屈折）を使い、MeshPhysicalMaterial の transmission は使わない。transmission は描画を1回分余計に行い、画面上の面積に比例して重くなるため
- 仕組み: 毎フレーム、背景（BackdropGradient）だけを半分の解像度の RenderTarget に描く。玉のシェーダーは `refract(viewDir, normal, 1.0/1.5)` で求めた方向で画面座標をずらし、この RenderTarget を読む。これで玉の中に背景が上下逆さに歪んで見える
- 反射: three.js の RoomEnvironment を PMREMGenerator に通した envMap を使う。Schlick のフレネル（F0 = 0.04）で屈折と反射を混ぜる
- 色: ガラスの吸収（Beer–Lambert の近似）で付ける。中心を通る光ほど濃くする。厚みは `2.0 * dot(N, V)` で近似し、`exp(-absorb * thickness)` で減衰させる
  - 赤（Ruby）: 吸収色は 1 − #FF3B5C、absorb = 1.6
  - 青（Sapphire）: 吸収色は 1 − #2E7BFF、absorb = 1.6
- ハイライト: 鋭い点状のハイライトを1つ置く（roughness 相当 0.05）。左上の光源方向は (−0.4, 0.8, 0.45)
- 縁の光: rim = pow(1 − dot(N, V), 3.0) × 0.35 を白で足す
- 影: 玉の真下に、ぼかした楕円の板（contact shadow。不透明度 0.25）を置く。シャドウマップは使わない
- 形: SphereGeometry(0.46, 48, 32)。盤のマス間隔は 1.0
- 勝った列: 揃った4つの玉に、emissive 相当の光（自分の色、強さ 0→1.2、0.6秒、easeOutCubic）を足し、そのあと 1.6秒周期で 0.8〜1.2 の間を脈打たせる
- 落とし穴: RenderTarget の色空間を合わせる。devicePixelRatio は 2 を上限にする

### 芯2: ColumnFlip（列の反転の演出と物理）
- ルール上の動き: 列の中の玉は常に底へ詰まっている。反転すると、玉の並び順を逆にする（底へ詰まったまま）。例: 底から [青, 赤] → [赤, 青]
- 盤の構成: 盤は独立した7本の ColumnTube（縦長のガラスの筒）と、土台の枠でできている。反転は ColumnTube 1本だけを動かす
- 演出の順番:
  1. 入力をロックする。筒の中の玉を Rapier 上で kinematic にし、筒の子として固定する
  2. 筒を X 軸まわりに 180° 回す。0.42秒、easeInOutCubic。回転の途中で、筒を手前へ z = +0.6 だけ浮かせる（sin カーブ）
  3. 回り終えた瞬間、玉は筒の上側にある。玉を dynamic に戻し、重力で底まで落とす
  4. すべての玉が止まったら（SettleDetector）、ルール上の位置へ吸着させ、入力のロックを外す
- 物理（Rapier2D、盤の面上）:
  - 重力: (0, −38) マス/s²
  - 玉: 円、半径 0.46、密度 1.0、restitution 0.32、friction 0.05
  - 筒の壁と底: 静的なコライダー、restitution 0.32
  - 反発の結合則: Max
  - 列ごとに collision group を分ける
- SettleDetector: 列のすべての玉の速さが 0.08 マス/s 未満の状態が 120ms 続くか、動き始めから 1.4秒経ったら「止まった」とみなす。止まったら、ルール上のマス位置へ 90ms（easeOutQuad）で吸着させる
- 落とす操作: 玉は盤の上端から y = +1.2 の位置に、速さ 0 で出す。左右のずれは ±0.02 の乱数
- 落とし穴: Rapier の WASM は `await RAPIER.init()` が終わるまで使えない。物理のステップは 1/120 秒の固定ステップにし、描画との差は補間する

### GameRules（純粋なロジック。物理と描画を知らない）
- 盤は 7列×6段。手番は赤が先手
- 1手は `drop(col)` か `flip(col)` のどちらか
- drop: 列が満杯なら指せない
- flip: 列の玉が2個以上で、かつ相手が直前の手で反転した列ではない、かつ自分の反転の残り回数が1以上のときだけ指せる。全部同じ色の列も反転できる（盤は変わらないが1手として数える）
- 反転の回数制限: 1ゲームで先手（赤）は2回、後手（青）は3回まで。反転すると自分の残り回数が1減る。先手の有利を減らすため（2026-10-25 に追加）
- 判定（毎手のあと）: 指した側に4つ揃いがあれば指した側の勝ち（両者に揃いがあるときも、指した側の勝ち）。相手だけに揃いがあれば相手の勝ち。どちらも無く、盤の42マスが全部埋まっていれば引き分け
- `legalActions(state)` と `apply(state, action)` は、新しい state を返す純粋な関数にする

### InputController（操作）
- 画面の下に Liquid Glass 風の切り替えボタン「落とす｜反転」を置く。手番が変わると「落とす」に戻る
- 「反転」のボタンに、手番の人の反転の残り回数を「反転 あと2」のように出す。残りが0のときはボタンを暗くし、押しても反転モードにしない
- 列を触る（pointerdown）と、その列を光らせる。同じ列で指を離す（pointerup）と、その手を指す。違う列で離したら取り消す
- 反転モードでは、反転できない列を不透明度 0.35 に暗くする
- 演出中（ロック中）の入力は捨てる

### GlassSound（Web Audio で合成）
- コツッ: 正弦波 2200Hz と 3150Hz（音量比 1 : 0.5）。減衰は exponential で 70ms。頭に 4ms の白色雑音（highpass 3000Hz）を重ねる。音量は衝突の強さ（Rapier の contact force event）に比例させ、0.05〜0.9 にする。高さは毎回 ±4% の乱数でずらす。同じ玉では 40ms 以内に2回鳴らさない
- 反転: 白色雑音を bandpass に通し、中心周波数を 400Hz → 1800Hz へ 0.42秒で動かす。音量 0.25
- 勝ち: ガラスのチャイム（上と同じ音色）で C6・E6・G6・C7 を 90ms 間隔で鳴らす
- 最初の pointerup の中で `audioCtx.resume()` を呼ぶ。右上に音のオン/オフのボタンを置く

### LiquidGlassUI（CSS のボタン・表示）
- `backdrop-filter: blur(18px) saturate(180%)`、`background: rgba(255,255,255,0.12)`、`border: 1px solid rgba(255,255,255,0.35)`、`box-shadow: inset 0 1px 0 rgba(255,255,255,0.6), 0 8px 24px rgba(0,0,0,0.25)`、`border-radius: 999px`
- 画面の上に手番の表示（色の玉のアイコンと「赤の番」「青の番」）を置く。勝負が付いたら、中央に「赤の勝ち」「青の勝ち」「引き分け」と「もう一度」ボタンを出す
- SVG の feDisplacementMap による屈折は使わない

### BackdropGradient（背景）
- 画面いっぱいの板に、4色のメッシュグラデーションをシェーダーで描く。色は #141A3A（左上）、#4B2E83（右上）、#C86B98（左下）、#F2A68B（右下）。色の位置は 30秒周期でゆっくり漂わせる
- 勝負が付いたら、勝った側の色（#FF3B5C か #2E7BFF）を 1.2秒で 40% 混ぜる

### BoardGlass（盤）
- MeshPhysicalMaterial（transmission は使わない）。color #FFFFFF、opacity 0.18、roughness 0.12、clearcoat 1.0、clearcoatRoughness 0.05、envMapIntensity 1.2
- 筒の縁に、太さ 0.02 の明るい線（不透明度 0.5）を引く
- カメラ: PerspectiveCamera（fov 30）。正面から少し見下ろす（俯角 6°）。盤の幅が画面の幅の 92% になるように距離を決める

## 6. 確かめる仕掛け
- URL に `?debug=1` を付けると、Rapier のコライダーの線、GameRules の盤面の文字表示、FPS、SettleDetector の状態（動いている列を赤で表示）を重ねて出す

## 7. 受け入れ条件
- [ ] GameRules の Vitest が通る。縦・横・2方向の斜めの勝ち／反転で上から赤・青の列が上から青・赤になる／反転の残り回数は赤2・青3から始まり、0になると反転できない／玉が1個以下の列は反転できない／相手が直前に反転した列は反転できない／反転で両者に揃いができたら指した側の勝ち／相手だけに揃いができたら相手の勝ち／42マス埋まって揃いが無ければ引き分け（`npm test`）
- [ ] `npm run build` が警告なしで通る
- [ ] 390×844 で開き、玉を落とすと底で跳ねて止まり、音が鳴る（Playwright。音は AudioContext の state が running であることで確かめる）
- [ ] 反転モードで玉が2個以上の列を触ると、筒が回り、玉が落ち直し、`?debug=1` の盤面表示が逆順になる
- [ ] 演出中に連打しても、1手しか進まない
- [ ] 実機の iPhone（Safari）で、落下と反転の最中も 55fps 以上を保つ（実機が無ければ、確かめていないと報告する）
